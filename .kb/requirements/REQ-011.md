All KB writes go through `kb_upsert/2` which validates the changeset schema before
committing. The RDF store is append-only; history is preserved via `rdf_persistency`.

## Why
Agents write most of the KB, so every write has to pass validation before it lands, and history has to survive so a bad change can be traced. Inferred from: README "Agents own the routine work"; ADR-023 and ADR-024 on audited, journaled writes.
