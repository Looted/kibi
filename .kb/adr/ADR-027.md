## Context

The proof layer previously hardcoded Playwright concepts: a
`kibi.playwright-run.v1` artifact family, `project` as the execution
dimension, numeric `retries`, a Cartesian `required_case_symbols ×
required_projects` coverage matrix, and a `kibi verify` command. This made
proof transport-specific: API projects, libraries, databases, and non-JS
ecosystems did not fit, while the proof wrapper could already run arbitrary
commands. Playwright was an accidental coupling, not part of the proof model.

## Decision

Kibi does not support test runners. Kibi supports proof evidence.

- One contract family: `kibi.proof-contract.v1` with explicit
  `required_proofs` (`symbol_id` + ecosystem-neutral `target`) executed by a
  configured integration, plus optional `proof_bindings` for native-runner
  provenance.
- One evidence envelope: `kibi.proof-run.v1` with producer/executor
  provenance, exact command, typed environment, run-level outcome, and
  factual attempt history (`complete` or `unavailable` — never inferred).
- One receipt family: `kibi.proof-receipt.v1`, engine-derived, bound to the
  live snapshot, contract hash, and an effective execution fingerprint
  covering only execution-relevant integration semantics. Receipt identity is
  deterministic (artifact digest + test + fingerprint), so re-ingestion is
  idempotent and one suite artifact can be evaluated independently against
  many TEST contracts.
- One ingestion path: `kb_ingest_proof`. The `kibi verify` command and the
  Playwright-specific protocol are removed without compatibility shims.
- Producers are isolated: the evidence engine depends only on the canonical
  envelope. Playwright becomes one first-party producer; JUnit/TAP adapters
  and a universal command-proof producer (exit-code floor for every project)
  are separate components.
- Integration configuration lives in tracked `.kb/proof/integrations.json`
  (`kibi.proof-integration.v1`), authored by bootstrap after deterministic
  `kibi proof inspect` discovery — never by `kibi init`, which stays
  infrastructure-only. Greenfield repositories without a harness record proof
  integration as deferred.
- `kibi prove` is the single execution vocabulary for humans, agents, and CI.
- Kibi stays opinionated about sufficiency: proof means all required
  obligations have fresh, passing evidence at the required
  `verification_scope` and `verification_perspective`. Attempt history is
  never upgraded from unknown to known; strict first-attempt policy fails
  closed.

## Consequences

- Old verification requirements, contracts, receipts, commands, schemas, and
  fixtures were migrated or deleted; after the cutover there is exactly one
  proof architecture and vocabulary.
- Cosmetic configuration edits do not stale proof; execution-relevant edits
  do, and diagnostics can name the drifted component.
- Local evidence is trusted as part of the local execution environment;
  adapters can lie just as reporters can. Attestation, if ever needed, is a
  separate future layer.
