## Context

Previous implementation patterns (learning from example product repositories) showed that static Kibi guidance often leads to high noise levels and wasted token budget. For example, agents were getting "Kibi-first" nudges even in repositories that were not yet initialized or when editing non-Kibi files. Additionally, agents were occasionally attempting to manually edit `.kb/` files, which bypasses the Kibi engine's logic and risks data corruption.

## Decision

We will implement a **smart, posture-aware enforcement architecture** for the OpenCode Kibi Plugin.

1.  **Posture Detection**: The plugin will detect the repository's Kibi state (`root_active`, `root_partial`, `root_uninitialized`, `vendored_only`, `hybrid_root_plus_vendored`) and apply a `maintenance_degraded` overlay when maintenance execution is unavailable.
2.  **Risk Taxonomy**: We will use a risk-based classification system for all agent actions to determine the enforcement level:
    -   `safe_docs_only` / `safe_test_only` (Low risk)
    -   `kb_doc_structural` (Medium risk)
    -   `req_policy_candidate` / `behavior_candidate` / `traceability_candidate` (High risk)
    -   `manual_kb_edit` (Critical risk - direct `.kb/` edit)
3.  **Advisory Default with Hook Guarantees**: Enforcement will be advisory (prompts/toasts) by default, providing high-signal guidance without blocking the editor. We will rely on Kibi's existing git hooks as the final "hard guarantee" for data integrity and traceability.
4.  **Concise Guidance**: Guidance will follow a strict token-budget policy (max 1 block, 5 bullets, 120 words) to minimize context window usage.
5.  **MCP-Only Surface**: All guidance must use MCP-only terminology, as decided in ADR-018, to maintain a clean agent-facing surface.

## Rationale

-   **Reduces Noise**: By only providing guidance when relevant (posture-aware) and proportional (risk-based), we significantly improve the developer/agent experience.
-   **Preserves Context**: The token-budget policy ensures that Kibi guidance doesn't overwhelm the agent's context window.
-   **Protects Integrity**: The `manual_kb_edit` risk class and corresponding warnings protect the internal Kibi state from accidental corruption by agents.
-   **Leverages Existing Hooks**: By relying on git hooks for hard guarantees, we keep the plugin logic simple and non-blocking while still enforcing critical rules.

## Consequences

-   **Development Cost**: Initial effort to implement posture detection and risk classification logic.
-   **Token Savings**: Reduced token consumption due to more concise and less frequent guidance.
-   **Improved Reliability**: Fewer manual edits to `.kb/` files and better traceability overall.
-   **Traceability Requirement**: All new plugin code must implement `REQ-opencode-smart-enforcement-v1`.
-   **Testing Requirement**: New regression tests for posture detection, risk classification, and token budget compliance.
