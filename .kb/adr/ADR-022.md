## Context

Kibi's public operation surface is already exposed through more than one route, but active guidance still treats the surfaces as if one were the only public path. That creates avoidable drift in docs, prompts, and policy checks.

## Decision

MCP and CLI are peer public operation surfaces. Public guidance, requirements, scenarios, and tests must describe them as peers, not as one primary surface with one hidden fallback.

The public surface definition belongs in requirements and validation, not in historical prose.

## Consequences

- New governance and traceability docs must preserve parity across both surfaces.
- Agent-facing material must stop implying that only one surface is public.
- Historical records stay intact, and supersession is expressed through links and metadata.

## Why this changed
Guidance still treated one public surface as the only path, which caused drift in docs, prompts and policy checks. MCP and CLI are now peer surfaces. Source: ADR-022 Context; commit "define MCP and CLI operation parity", Jul 21.
