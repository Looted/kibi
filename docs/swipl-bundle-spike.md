# SWI-Prolog bundle spike

This is the first checkpoint for shipping SWI-Prolog inside Kibi's platform npm packages. It tests whether a trimmed, GMP-free SWI-Prolog prefix can move to a new directory and run Kibi's Prolog and CLI suites. The spike does not change SWI-Prolog installation or interpreter lookup behavior.

The fourth Actions attempt passed the complete phase 1 native checkpoint on both prescribed targets. The [phase 2 build pipeline](swipl-build.md) is implemented; its four-platform Actions checkpoint is pending. The earlier failed attempts remain recorded below.

The [spike workflow](../.github/workflows/swipl-spike.yml) builds only on GitHub Actions: Linux x64 inside `manylinux_2_28` and macOS arm64 on `macos-14`, targeting macOS 12. Each job fails if `swipl` is already on `PATH`. Native sources come from SHA-256-pinned archives listed in [swipl-version.json](../scripts/swipl-version.json). SWI-Prolog remains pinned to 10.0.2; the vendored dependency versions are OpenSSL 3.5.9 LTS, PCRE2 10.47, and zlib 1.3.2. Their source archives were checked before pinning. OpenSSL 3.5 and PCRE2 10.47 avoid known maintenance and security issues in older candidate versions.

The build uses `USE_GMP=OFF` and `USE_LIBBF=ON`, disables X, Java, ODBC, BerkeleyDB, GUI, docs, and unused package sets, and keeps the C extensions and Prolog libraries Kibi needs. The test checks unbounded integers at runtime and loads every required library, including `prolog_coverage`. Installed executables, libraries, and license texts are copied to a different directory. The original build, dependency, and install trees are removed before any runtime test. Every ELF or Mach-O file is audited; Linux dependencies may resolve only to the staged OpenSSL, PCRE2, zlib, SWI libraries or the specified glibc runtime libraries. macOS dependencies are rewritten relative to their loader, signed ad hoc, and checked for a deployment target no later than macOS 12.

Both jobs run all three Prolog test files (`kb.plt`, `logic_ir.plt`, and `schema.plt`) under the existing 50% coverage floor, then run the canonical full CLI batch with test isolation. The workflow uploads the relocated prefix tarball and a report containing installed and packed sizes plus the outcome of each check. It can run from the `codex/swipl-bundle-spike` branch on relevant changes or by `workflow_dispatch`. Locally, `bash scripts/swipl-spike.sh verify-config` validates the pins and target without building native code.

Preparing the three-file run exposed a defect in the existing coverage runner: repeated `--test` arguments loaded only the first test file. The runner now enumerates every requested file and includes all of their directories in the coverage report. A regression test proves a failing later file makes the run fail.

The first [Actions spike run](https://github.com/Looted/kibi/actions/runs/36696670860) stopped on macOS arm64 at 64% of the SWI build. The recipe forced `HAVE_CRYPT=0` and `HAVE_LIBCRYPT=0`, which selected SWI's `bsd-crypt.c` fallback. That source includes `crypt.h` on non-Windows hosts, while the macOS runner's SDK has no `crypt.h`. Compilation failed before relocation, smoke checks, suites, or size measurements. The phase 1 exit criterion is therefore unmet; this is a diagnosis of the failed recipe, not a verified portable build.

In the first run, Linux built and relocated SWI-Prolog 10.0.2 successfully. The ELF dependency audit, LibBF integer check, all required-library loads, and all 256 Prolog tests passed. Its full CLI batch had 10 failures: eight permission-refusal tests use `chmod 000`, which did not deny access to the container's root user; one init test encountered Git's dubious-ownership refusal in the checkout instead of its mocked branch error; and one generated-manifest hook test hardcodes `/usr/bin/git`, while this container uses `/usr/local/bin/git`. Those observed test-environment mismatches prevented the first run from passing its full CLI suite. The workflow recorded both sizes in `report.json`, but the uploaded artifact retained only that report, not the tarball. The upload step used a host `runner.temp` path while the container built under `/__w/_temp`; that path mismatch is the likely cause of the first missing tarball.

The second phase 1 attempt repairs those specific blockers. On macOS, the recipe now lets SWI probe the platform's `crypt` function instead of forcing its `crypt.h`-dependent fallback; Linux retains its explicit no-`libcrypt` build. Inside manylinux, the build and suites now run as a dedicated unprivileged user with an owned checkout, home, work directory, and accessible Bun binary. The CLI fixtures resolve the runner's Git executable and run the mocked init error in a fresh test Git workspace. Both jobs pass the actual `$RUNNER_TEMP` directory to build and artifact upload, and a successful job verifies that its report and tarball are nonempty.

The first new CLI failure is a production engine socket-path defect: a fixture sets `KIBI_RUNTIME_DIR` to a long macOS temporary directory, producing a 114-byte Unix socket path that fails with `listen EINVAL`. The engine selects writable runtime directories without checking the resulting socket's byte length. [Darwin's socket structure](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/sys/un.h) has a 104-byte path field, and [the pinned Node/libuv implementation](https://raw.githubusercontent.com/nodejs/node/v24.21.0/deps/uv/src/unix/pipe.c) rejects longer paths. This establishes the observed 114-byte failure; it does not establish that the runner's default 104-byte path fails, and earlier tests using the default passed.

The 115 CLI failures span 32 files: 89 report source or relationship containment refusals, 15 directly show `/var` versus `/private/var` canonical-path mismatches, two expose engine identity mismatches, and one uses a Linux boot-ID fixture assumption. Together with the socket failure, these account for 108 tests. Seven need further reproduction: one in-flight query timeout, two disappearing Git maintenance-lock snapshots, and four unresolved assertions. These results do not attribute the full suite failure to the socket alone or establish that every failure is a portability defect. The third attempt stops at this failed checkpoint; no further runtime repair, assertion weakening, or subsequent phase is part of this attempt.

The fourth phase 1 repair passed both native jobs in [Actions run 36735277796](https://github.com/Looted/kibi/actions/runs/36735277796), on committed source head `58083a18`. Source authoring, apply-plan source writes, and relationship shards now compare canonical filesystem paths on both sides of their containment checks. Resolving the nearest existing ancestor preserves missing path suffixes beneath aliased roots such as `/var` and `/private/var`; traversal, derived-state writes, external symlink escapes, and dangling symlinks remain refused. Actual aliased-root mutation regressions pass, and unchanged pending-receipt and bootstrap assertions pass under an aliased temporary root, where the previous source failed. Canonical path fixtures now use the filesystem identity their production APIs return, while parity normalization retains both root spellings without discarding store-path suffixes or semantic differences. Boot-ID staleness evidence is used only when the host provides a boot ID; a live holder remains protected when that evidence is unavailable.

The engine now canonicalizes workspace identity consistently in clients, socket keys, and the daemon. Its Unix runtime selection budgets the complete UTF-8 socket path at 103 bytes on Darwin and 107 on Linux while preserving the 32-hex workspace/branch identity. An oversized or unsafe configured directory uses a deterministic per-user fallback under canonical `/tmp`, keyed by the canonical configured runtime identity so distinct configurations remain distinct. Existing runtime directories must be owned, private, and not symlinks; the engine does not chmod a user-specified directory. Socket, PID, start-lock, and publication-lock paths use the same location. Tests cover long explicit, XDG, and default TMPDIR paths, multibyte names, configuration/branch separation, unsafe directories, and a real typed daemon write/read/stop cycle across an aliased missing workspace. The owned test runner also creates its Unix runtime in a short private `/tmp` directory, keeping its PID cleanup attached to the actual socket directory; its real-engine cleanup regression passes under a long aliased TMPDIR.

README detection now chooses the actual directory-entry spelling in its existing priority order, including on case-insensitive filesystems, while retaining broken-symlink refusal. The two Git snapshot fixtures disable detached auto-maintenance for their fixture commits so maintenance cannot change `.git` during the snapshot assertion. The abort fixture waits for a real Prolog started/release barrier before cancelling an executing query, then verifies that the same daemon, socket, and sibling client remain usable within the original 20-second bound. This repairs the test's synchronization without claiming a confirmed production cause for its previous timeout.

The stale-status case exposed a separate native timestamp defect. Pinned SWI-Prolog 10.0.2 reads nanoseconds through `st_mtim` when its CMake probe succeeds, otherwise it returns integer seconds. The Darwin probe failed and there was no `st_mtimespec` alternative, allowing a real same-second workspace edit to appear fresh; a later timestamp correctly appeared stale. The checked [three-file source patch](../scripts/patches/swipl-10.0.2-darwin-mtime.patch) adds a real `st_mtimespec` probe, configuration macro, and seconds-plus-nanoseconds branch, preserving `st_mtim` as the first choice and the existing fallback. The manifest pins the upstream archive, patch SHA-256, and all three original and patched file hashes. Application verifies that inventory, rejects unknown or partially patched source, and leaves an already patched source unchanged. Both retained reports match the source head's upstream and patch pins. The fourth Darwin log confirms that the new `st_mtimespec` probe succeeds after `st_mtim` fails. Both relocated runtimes pass the new smoke check with exact same-second file times `1600000000.125` and `1600000000.875`.
