# SWI-Prolog bundle spike

This is the first checkpoint for shipping SWI-Prolog inside Kibi's platform npm packages. It tests whether a trimmed, GMP-free SWI-Prolog prefix can move to a new directory and run Kibi's Prolog and CLI suites. The spike does not change Kibi's installation or runtime lookup behavior.

The [spike workflow](../.github/workflows/swipl-spike.yml) builds only on GitHub Actions: Linux x64 inside `manylinux_2_28` and macOS arm64 on `macos-14`, targeting macOS 12. Each job fails if `swipl` is already on `PATH`. Native sources come from SHA-256-pinned archives listed in [swipl-version.json](../scripts/swipl-version.json). SWI-Prolog remains pinned to 10.0.2; the vendored dependency versions are OpenSSL 3.5.9 LTS, PCRE2 10.47, and zlib 1.3.2. Their source archives were checked before pinning. OpenSSL 3.5 and PCRE2 10.47 avoid known maintenance and security issues in older candidate versions.

The build uses `USE_GMP=OFF` and `USE_LIBBF=ON`, disables X, Java, ODBC, BerkeleyDB, GUI, docs, and unused package sets, and keeps the C extensions and Prolog libraries Kibi needs. The test checks unbounded integers at runtime and loads every required library, including `prolog_coverage`. Installed executables, libraries, and license texts are copied to a different directory. The original build, dependency, and install trees are removed before any runtime test. Every ELF or Mach-O file is audited; Linux dependencies may resolve only to the staged OpenSSL, PCRE2, zlib, SWI libraries or the specified glibc runtime libraries. macOS dependencies are rewritten relative to their loader, signed ad hoc, and checked for a deployment target no later than macOS 12.

Both jobs run all three Prolog test files (`kb.plt`, `logic_ir.plt`, and `schema.plt`) under the existing 50% coverage floor, then run the canonical full CLI batch with test isolation. The workflow uploads the relocated prefix tarball and a report containing installed and packed sizes plus the outcome of each check. It can run from the `codex/swipl-bundle-spike` branch on relevant changes or by `workflow_dispatch`. Locally, `bash scripts/swipl-spike.sh verify-config` validates the pins and target without building native code.

Preparing the three-file run exposed a defect in the existing coverage runner: repeated `--test` arguments loaded only the first test file. The runner now enumerates every requested file and includes all of their directories in the coverage report. A regression test proves a failing later file makes the run fail.

Phase 2 can start only after both native platforms pass the complete phase 1 checkpoint. Its build workflow and package pipeline will use the measured, reviewed build recipe. macOS Intel and Linux arm64 belong to that subsequent platform matrix; this phase measures the two prescribed initial targets.

The first [Actions spike run](https://github.com/Looted/kibi/actions/runs/36696670860) stopped on macOS arm64 at 64% of the SWI build. The recipe forced `HAVE_CRYPT=0` and `HAVE_LIBCRYPT=0`, which selected SWI's `bsd-crypt.c` fallback. That source includes `crypt.h` on non-Windows hosts, while the macOS runner's SDK has no `crypt.h`. Compilation failed before relocation, smoke checks, suites, or size measurements. The phase 1 exit criterion is therefore unmet; this is a diagnosis of the failed recipe, not a verified portable build.

In the first run, Linux built and relocated SWI-Prolog 10.0.2 successfully. The ELF dependency audit, LibBF integer check, all required-library loads, and all 256 Prolog tests passed. Its full CLI batch had 10 failures: eight permission-refusal tests use `chmod 000`, which did not deny access to the container's root user; one init test encountered Git's dubious-ownership refusal in the checkout instead of its mocked branch error; and one generated-manifest hook test hardcodes `/usr/bin/git`, while this container uses `/usr/local/bin/git`. Those observed test-environment mismatches prevented the first run from passing its full CLI suite. The workflow recorded both sizes in `report.json`, but the uploaded artifact retained only that report, not the tarball. The upload step used a host `runner.temp` path while the container built under `/__w/_temp`; that path mismatch is the likely cause of the first missing tarball.

The second phase 1 attempt repairs those specific blockers. On macOS, the recipe now lets SWI probe the platform's `crypt` function instead of forcing its `crypt.h`-dependent fallback; Linux retains its explicit no-`libcrypt` build. Inside manylinux, the build and suites now run as a dedicated unprivileged user with an owned checkout, home, work directory, and accessible Bun binary. The CLI fixtures resolve the runner's Git executable and run the mocked init error in a fresh test Git workspace. Both jobs pass the actual `$RUNNER_TEMP` directory to build and artifact upload, and a successful job verifies that its report and tarball are nonempty.

The macOS job then failed at `bun run build`, before either suite started. `kibi-codex` runs the canonical skill generator, which calls `withSharedAdoptionLock` and `withExclusiveMirrorWriterLock`. Their shared backend in `scripts/skillopt-eval/adoption-lock.ts` binds `flock` only on Linux and throws `Linux adoption locks unavailable` on Darwin. This is a repository build portability defect; the report records `build: failed` and contains no Prolog or CLI suite result. There is no observed GMP-only failure.

The second attempt stopped with phase 1 failed and later phases gated. Its next repair required a Darwin native `flock` backend while preserving the descriptor ownership, permission, inode, symlink, lock ordering, and release guarantees. That attempt did not change the lock implementation or bypass the full build.

The third phase 1 attempt adds the Darwin binding used by canonical skill-mirror generation: `flock` comes from `/usr/lib/libSystem.B.dylib` on Darwin and `libc.so.6` on Linux. The validated descriptor, shared/exclusive flags, private ownership and mode checks, symlink/hardlink and inode checks, lock ordering, and release flow are preserved. Unsupported platforms reject all three lock operations before creating `.kibi` state or entering the operation. This extends the generator's native lock backend; it does not claim the entire SkillOpt adoption workflow is supported on Darwin.

Both native jobs now run the existing lock security, contention, process-termination release, and hardlink tests, plus a real locked Codex mirror write/check regression, before starting the expensive build. Linux runs these tests inside the same unprivileged-user wrapper as the native checkpoint; Darwin runs them directly on its arm64 runner. Local Linux verification passed all 30 tests in that focused batch. The complete affected batch (`scripts/skillopt-eval/tests`, `scripts/tests`, and `test/root-summary.test.ts`) then passed 1,066 tests across 188 files with zero failures, isolation, and the existing 15-second per-test bound. Scripts TypeScript and formatting checks also passed. These local results exercise the Linux backend; the third native Actions attempt remains pending and must verify Darwin behavior.

The broader local run first exposed an existing broker fixture defect: Bun represents an ambient empty `NODE_TLS_REJECT_UNAUTHORIZED` as an enumerable undefined value, and spreading it into an explicit launch environment violates the required string-valued schema. The fixture now inherits only string values before setting its fixed evaluation branch; production validation and all runtime-query assertions remain unchanged. Its isolated empty-environment reproducer passed all nine tests, and the complete affected batch above passed with that same empty ambient variable present. The checkpoint still requires the complete repository build, all three Prolog files with the 50% coverage floor, and the full isolated CLI batch to pass on both native platforms before phase 2 can start.

The same pull request also repairs standard CI. Its strict-proof contract still requires equality for every current requirement; the explicit assertion is raised from 122 to 125 to cover the expanded requirement set, including the new scripts coverage requirement. Local targeted proof on repair snapshot `a260a346` reports 125/125 proven with zero unresolved. Committed head `38d96916` passed strict baseline equality at 125/125 proven with zero proof gaps, violations, or fingerprint changes, and typed status was fresh with `dirty: false` and `proofSnapshotDirty: false`. The complete local scripts batch passed all 253 tests across 34 files, including the 125-requirement contract. The scripts coverage shard now runs each discovered test file in its own process, preserving the complete test set and the 15-second per-test limit. All 34 files passed locally with that isolation; its selected-shard LCOV measured 42.70% line coverage, with the full-repository coverage gates omitted for this subset. Three unrelated subprocess tests reached the limit with empty output in the shared Bun coverage process, while isolated runs completed quickly. Shared-process interference is the working diagnosis; fresh standard CI must confirm that isolation resolves it. Standard PR CI has not started on this head because the PR conflicts with `develop`. Repository proof does not certify native relocation or replace the failed phase 1 checkpoint.
