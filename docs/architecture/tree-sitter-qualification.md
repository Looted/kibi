# Tree-sitter distribution qualification

## Decision

Use the standard `web-tree-sitter` runtime at exactly 0.27.0 with three pinned upstream grammar WASM files for the first plugin release: Python 0.25.0, Go 0.25.0, and Rust 0.24.0. Keep the runtime and grammar assets inside the installed package closure. The parser path makes no runtime network requests and needs no compiler or language toolchain on a consuming machine.

The official npm grammar packages include a prebuilt `.wasm`, the exact source query set, and the repository MIT license in the same versioned tarball. Pinning each package tarball by its registry SHA-512 SRI, its `gitHead` source commit, and the SHA-256 of the extracted WASM/query files gives a small, auditable asset set. The plugin ships only those parser binaries, the `tags.scm` queries, and the MIT texts; it does not ship the grammar packages' native addons or build sources.

## Runtime and ABI evidence

The `web-tree-sitter@0.27.0` npm archive is 1,161,704 bytes packed and 4,683,395 bytes unpacked. Its package includes the JS runtime and adjacent `web-tree-sitter.wasm`. The official web binding documents support for parser ABI 13 through 15. The selected grammar modules report ABI 15 for Python and Go, and ABI 14 for Rust. All three loaded through `Language.load`, compiled their upstream `tags.scm` with `Query`, parsed fixtures, and produced declaration captures in both Node.js 24.21.0 and Bun 1.4.2. The smoke run replaced `globalThis.fetch` with a throwing function before importing the runtime; parsing still succeeded from local files.

The copied upstream `tags.scm` files retain their source commits. Go's query includes `#strip!` and `#set-adjacent!` directives; the pinned web runtime accepted the query and returned captures in both tested runtimes. Rust's stock tags can match an impl method through both the method and general-function patterns, so the adapter classifies by enclosing impl/trait and deduplicates by the source name range. The Rust grammar uses `function_signature_item` for trait declarations, which the upstream tags query omits; the package adds a separately cataloged Kibi-authored query overlay for those method signatures.

The three grammar WASM assets total 1,780,253 bytes unpacked (Python 457,883; Go 217,182; Rust 1,102,547). The upstream `.wasm` packages directly record exact npm artifact integrity; `catalog.json` includes the registry SRI, `gitHead` commit, parser ABI, scanner status, query origin, and SHA-256 for every vendored parser and query. `integrity.json` independently checks the shipped package files before packing.

## Rejected reuse candidate

[`@xberg-io/tree-sitter-language-pack@1.20.0`](https://registry.npmjs.org/@xberg-io/tree-sitter-language-pack/-/tree-sitter-language-pack-1.20.0.tgz), from [xberg-io/tree-sitter-language-pack](https://github.com/xberg-io/tree-sitter-language-pack), publishes a Node binding with N-API binaries for eight platform/architecture combinations. Its archive is 17,261,921 bytes packed and 40,243,951 bytes unpacked, requires Node 22 or later, and documents downloading parsers on first use into a local cache. That is not an offline-ready, platform-neutral parser closure for Kibi's installed plugin. Its parser and Node APIs are also its own binding API, so the Kibi integration would depend on the package's normalized extraction surface instead of the ordinary Tree-sitter query/runtime contract.

The separate [`@xberg-io/tree-sitter-language-pack-wasm@1.20.0`](https://registry.npmjs.org/@xberg-io/tree-sitter-language-pack-wasm/-/tree-sitter-language-pack-wasm-1.20.0.tgz) archive is 5,227,478 bytes packed and 56,568,778 bytes unpacked, including one 56,342,439-byte self-contained WASM module. It is MIT and its README says it has no runtime downloads, but it is a Rust/wasm-bindgen API bundle, not a grammar module for `web-tree-sitter`. Its curated built-in `process()` extraction API can parse Python, Go, and Rust, but it would couple Kibi to a second Tree-sitter binding and its own normalized results. The xberg Node and WASM package versions and registry integrities are recorded in the research notes for this qualification; neither is a runtime dependency.

The broad [`tree-sitter-wasms@0.1.13` npm tarball](https://registry.npmjs.org/tree-sitter-wasms/-/tree-sitter-wasms-0.1.13.tgz) is not used: it is 4,535,492 bytes packed / 51,769,841 bytes unpacked, contains 37 grammars, declares Unlicense at package level, and does not ship a per-grammar license inventory. Its measured registry SRI is `sha512-wT+cR6DwaIz80/vho3AvSF0N4txuNx/5bcRKoXouOfClpxh/qqrF4URNLQXbbt8MaAxeksZcZd1j8gcGjc+QxQ==`. The small set of official language packages gives better provenance for the exact parsers and scanners shipped.

## License and scanner review

The chosen runtime and each selected grammar package declare MIT and include a corresponding repository `LICENSE`. Python 0.25.0 contains an external `src/scanner.c`; Rust 0.24.0 contains an external `src/scanner.c`; each scanner is in the same pinned source repository and covered by that repository's MIT license. Go 0.25.0 has no external scanner. The upstream `queries/tags.scm` files are likewise from those same MIT-licensed source commits. Copies of all four license texts and an SPDX 2.3 component list ship with the plugin.

This is a qualification of the exact artifacts in this catalog, not a blanket approval of every grammar in either language-pack project. Adding a language requires a new versioned source package, scanner/query and license review, ABI check, asset hashes, fixture evidence, and an updated SBOM before it can be shipped.

## Limits and remaining checks

`ok` means the selected catalog query found the qualified syntactic declarations; it does not certify the full runtime symbol set. The parser does not expand Rust macros, run Python decorators/metaclasses, evaluate Python `exec()`, or discover generated files outside the analyzed input. Detected Rust macro invocations and direct Python `exec()` calls are marked `partial`; other dynamic declaration mechanisms remain an explicit limitation of this syntactic contract. The plugin exposes parser-derived declarations, not types, a complete call graph, or build semantics. A parse error, output cap, unsupported file, oversized input, worker error, or timeout stays explicit in the v2 result. The parsing worker constrains time, V8 heap, concurrency, input, and symbol output; it is not an operating-system sandbox.

The registry artifact is pinned by npm SRI and its source commit, and the shipped files are SHA-256 checked. The rejected xberg Node tarball SRI is `sha512-96fnqUv1H378/6g4KcC2uuVgOILiCMwqNJy0f3w6ab57rNCLBPnlkzsPTsqie4x1VABHi9J0zJ9kBizE+gzKUw==`; its measured Node tarball URL is `https://registry.npmjs.org/@xberg-io/tree-sitter-language-pack/-/tree-sitter-language-pack-1.20.0.tgz`. The rejected xberg WASM tarball SRI is `sha512-bbLMsnWkW6cfyiSvfLpWx3A08D2fhNkT3xSfb6Q/0tAnL6M/8B4eomKd1sIKyZtadqv9AfEuYiKXH4Am29fUHA==`; its exact tarball URL is `https://registry.npmjs.org/@xberg-io/tree-sitter-language-pack-wasm/-/tree-sitter-language-pack-wasm-1.20.0.tgz`. These records establish the exact bytes selected for this plugin; they do not constitute an independent upstream build attestation for the grammar maintainers' `.wasm` compilation process. The controlled release should keep the catalog and approval digest tied to the final packed artifact.
