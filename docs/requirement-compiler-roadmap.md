# Prose-to-Prolog requirement compiler mission and roadmap

## Codex goal

Build Kibi into a conservative, end-to-end requirements compiler that preserves human-readable prose while decomposing every assertive proposition into a stable, source-bound semantic inventory. Each proposition must resolve to exactly one validated representation—a strict property, canonical predicate, safe `kibi.logic.v1` rule, or explicit unresolved state—and Prolog must produce inspectable proof outcomes for grounding and contradictions without treating ambiguity, missing ontology, or incomplete reasoning as consistency.

Close the loop from intent to executable behavior by proving, for every current normative requirement, a fresh chain from `REQ --specified_by--> SCEN --verified_by--> TEST`, from executable test symbols to that test via `executable_for`, and from production symbols to the requirement and test via `implements` and `covered_by`. A Codex run succeeds only when the prose is fully accounted for, no blocking contradiction remains, the required verification depth—including passing E2E evidence—is present, symbols resolve to current source coordinates, and every remaining gap is explicit, ranked, and repairable rather than hidden behind green structural counts.

## High-value implementation vectors

1. **Conservative proof report (P0, foundation implemented).** Keep legacy `coverageStatus` for compatibility, but add `proofStatus`, stage evidence, stable gap codes, and ranked repairs. Require a complete semantic ledger, one valid ground representation per modeled claim, a non-blocking contradiction outcome only after grounding, scenario-backed passing E2E evidence, executable test symbols, production ownership/coverage, and persisted source coordinates.
2. **Proposition completeness at ingestion (P0, foundation implemented).** The semantic advisor now emits a versioned source-field/hash contract, direct mutation preflight enforces exact claim text, UTF-8 spans, roles, statuses, and claim-key-to-grounding identity, and Markdown sync baselines legacy prose once before enforcing new or semantic edits. Continue with migration planning and richer Markdown/source-map handling rather than weakening explicit `ambiguous`, `ontology_gap`, `missing`, or `nonlogical` outcomes.
3. **Fresh proof receipts (P0, implemented).** Append-only proof-receipt history binds test identity, typed scope, integration command, deterministic workspace snapshot, canonical environment hash, execution fingerprint, timestamps, outcome, and artifact digest. Evidence is emitted as `kibi.proof-run.v1` by any producer (native, JUnit/TAP adapters, or universal command proof) and evaluated by `kb_ingest_proof` into `kibi.proof-receipt.v1` with deterministic, idempotent receipt identity. Coverage and status expose the live snapshot through CLI and MCP; proof fails closed for missing, wrong-snapshot, stale, failed, malformed, future-dated, or unavailable evidence while keeping durable status structural. Continue with signed/remote artifact attestations rather than weakening the default seven-day window.
4. **Ontology convergence and contradiction witnesses (P1, foundation implemented).** Project-local schemas now participate in deterministic ranking through their normalized RDF representation; incomplete ordered arguments produce no applicable write plan until the caller supplies exact bindings. Strict, predicate, and rule conflicts now return source-bound witnesses, while rule overlap that cannot be proved or excluded keeps proof explicitly `unresolved`. Continue with corpus-driven schema promotion and ranked legacy-property migrations.
5. **Repair-oriented migration (P1, read-only preview implemented).** Requirement coverage emits deterministic `kibi.repair-plan.v1` dependencies and opt-in `kibi.legacy-migration-plan.v1` proposition previews. The latter defaults to one requirement, reconstructs exact authored source, ranks project-local and built-in schemas with binding provenance, preserves conflicting code `text_ref` evidence, and withholds all writes. Continue with reviewed corpus application and measured proof-gap recovery rather than synthesizing unreviewed writes.
6. **Telemetry as an acceptance gate (P1, remediation implemented).** `kibi.telemetry-acceptance.v1` evaluates a fresh rolling event window for advisor-before-write use, exact validation-before-upsert, source-linked zero-result rate, proof-gap recovery, E2E receipt freshness, and repeated mutation failures. CLI JSON and MCP diagnostic records now preserve opaque session/actor correlation, and `kibi.telemetry-remediation.v1` enumerates exact unmatched events plus report-level missing evidence without mutating the KB. Continue with configurable project policies and durable trend snapshots rather than weakening the conservative defaults.
7. **Dogfood/pinned parity matrix (P2, implemented).** `kibi.distribution-parity.v1` runs the same semantic-inventory, contradiction-witness, conservative-proof, repair-plan, proof-receipt, and telemetry-acceptance fixtures through source, freshly packed CLI/MCP, and optionally project-resolved runtimes. Executable-derived provenance, conservative normalization, explicit unsupported states, and action-bound project divergences prevent a healthy dogfood project from masking a pinned-package regression—and vice versa.

## Next execution sequence

1. **Distribution parity — completed.** The versioned runner executes the six canonical cases through source, freshly packed CLI/MCP artifacts, and the actual dogfood project A/B runtime resolutions. It normalizes volatile evidence, preserves stable semantic identifiers, classifies unsupported capabilities explicitly, and requires a named upgrade or compatibility action for every project divergence.
2. **Correlated telemetry remediation — completed.** CLI JSON and MCP diagnostic paths preserve opaque session/actor identifiers; advisor and preflight matches cannot cross explicit correlation boundaries; and the read-only `usage-remediation` command emits a deterministic `kibi.telemetry-remediation.v1` report with exact log lines and explicit report-level evidence gaps. Durable daily trend snapshots and project adoption remain separate follow-up work.
3. **Turn legacy prose into reviewable migration batches — source separation completed.** The read-only planner now reconstructs source-bound proposition inventories, ranks exact project-local schemas, and emits one dependency-ordered preview batch by default through CLI and MCP. Requirement-only `semantic_text` now carries normalized authored prose without replacing independent `text_ref` evidence, and differing pre-existing semantic prose fails closed. Applying reviewed batches remains separate work: begin with one dogfood project B or dogfood project A batch, validate exact bindings, and measure proof-gap recovery before continuing.
4. **Promote ontology and verification evidence from local success to durable trust.** Mine repeated ontology gaps into candidate `predicate_schema` promotions with corpus witnesses and false-positive tests. In parallel, extend verification receipts with optional signed/remote artifact attestations and project-specific freshness policy while retaining the conservative seven-day default and the rule that missing or unverifiable evidence never counts as a pass.

The delivery order is deliberate: parity prevents dogfood from hiding packaged regressions; instrumentation makes the acceptance gate actionable; migration converts the two audited knowledge bases into proof-capable inputs; and ontology/attestation hardening scales correctness once the transport and evidence surfaces agree.

## Distribution parity readout

The first `kibi.distribution-parity.v1` audit resolved eight runtime surfaces and executed 48 capability observations with no execution failures or unactioned divergences. Source and freshly packed CLI/MCP matched for all 12 surface-capability pairs. Dogfood project B resolved pinned `kibi-cli` 0.14.0 and `kibi-mcp` 0.19.0; all 12 observations were explicitly unsupported, and each carries a named package-upgrade action. The harness ran those binaries only against disposable fixture repositories, leaving both audited knowledge bases untouched.

## Repair-plan field readout

The first `kibi.repair-plan.v1` audit makes the migration scale explicit. Dogfood project A's dogfood surface reports a complete plan for 85 actionable requirements: 505 batches, 85 ready and 420 dependency-blocked. Dogfood project B's pinned CLI exposes no repair plan and still labels all 39 requirements structurally not applicable; the current checkout, attached read-only to the same dogfood project B KB, reveals 33 actionable requirements with 198 batches, 33 ready and 165 blocked. This is direct evidence for making pinned/dogfood capability parity an acceptance dimension rather than inferring health from the older structural summary.

The first `kibi.legacy-migration-plan.v1` dogfood preview stayed read-only on both projects. Dogfood project A returned a review-ready authored-source batch with five propositions, one explicit ontology gap, and six ranked candidates; its project status remained in the pre-existing dirty/stale state. Dogfood project B initially blocked `REQ-021` because `text_ref` is `src/app/services/notification.service.ts:41`; the semantic-source separation slice now treats that path as independent evidence and previews authored prose through `semantic_text`. A current-checkout read-only rerun against the pinned dogfood project B returned `ready_for_review`, preserved that exact `text_ref`, and left both the KB byte hash and clean/fresh status unchanged. Four Markdown evidence-label/path lines are still classified as assertive missing propositions, so evidence-block classification should be corrected before applying this batch.

## Telemetry acceptance readout

The first 200-event `kibi.telemetry-acceptance.v1` window makes process debt inspectable. Dogfood project A's fresh dogfood log fails: 153/200 events carry complete telemetry, 6/7 requirement writes have a preceding advisor, 0/75 upserts have an exact recent validation, 2/3 source-linked lookups return zero results, and two mutation targets reached failure streaks of three or more. Its older coverage events lack the new proof/receipt fields, so those two metrics remain explicitly insufficient until current complete coverage is logged. Dogfood project B's newest pinned evidence is stale: it records 198/200 telemetry-complete events, 24/25 validated upserts, 1/7 source misses, and no three-failure target, but its last event is from 24 July 2026 and it has no observable proof/receipt recovery fields. Historical health therefore cannot prove current acceptance.
