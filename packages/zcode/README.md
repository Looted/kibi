# kibi-zcode

ZCode plugin adapter for Kibi: bundled Kibi skills, a `/kibi-bootstrap` slash
command, advisory lifecycle hooks, and the workspace-gated Kibi MCP server.

This package mirrors the architecture of `kibi-codex` (plugin manifest +
skills + hooks + MCP), declared in ZCode's native plugin format.

## Layout

- `.zcode-plugin/plugin.json` — ZCode plugin manifest (inline `mcpServers`)
- `bin/mcp-launcher.cjs` — stdio MCP launcher (silent outside Kibi workspaces)
- `hooks/hooks.json` — ZCode hook declarations
- `skills/` — generated mirror of the canonical Kibi skills
  (`packages/runtime/src/skills/`), frontmatter-rewritten for ZCode's skill
  loader; generated by `scripts/sync-agent-skills.ts --target zcode`, drift-checked by
  `tests/skill-drift.test.ts`
- `commands/kibi-bootstrap.md` — slash command routing into the
  `kibi-bootstrap` skill
- `src/` — hook runner and helpers (TypeScript, built to `dist/`)

## ZCode declaration contract

The plugin targets ZCode's documented plugin schema, verified against the
installed client:

- **Manifest** at `.zcode-plugin/plugin.json`; component paths must stay
  relative and inside the plugin root; the stdio `mcpServers` entry accepts
  only `command`, `args`, `cwd`, `env`, `enabled`, `timeoutMs` (unknown keys
  silently drop the server).
- **Hook events** used: `SessionStart`, `PreToolUse`, `PostToolUse`, `Stop`.
  Matchers are case-sensitive regexes tested against the tool name; an omitted
  matcher matches everything (a bare `*` is an invalid regex and would never
  match).
- **Hook output** is parsed as strict JSON: recognized top-level keys are
  `additionalContext`, `continue`, `decision`, `hookSpecificOutput`, `reason`,
  `stopReason`, `suppressOutput`, `systemMessage`; any extra key fails
  validation and discards the output. Context for the model is therefore
  emitted as `{"hookSpecificOutput": {"hookEventName": "<event>",
  "additionalContext": "…"}}`, where `hookEventName` must name the event that
  is actually running.
- **Skill frontmatter**: the loader marks a skill `safeToAutoLoad` only when
  every top-level frontmatter key is one of `name`, `description`,
  `when_to_use`, `license`, `metadata`. The zcode skills mirror therefore
  nests canonical kibi keys (`id`, `version`, `kibiCompatibility`, `tags`,
  `resources`) under `metadata:` and keeps bodies byte-identical.

## Hook behavior

All hooks are advisory; the hard enforcement gate remains the
`kibi check --staged` git hook installed by `kibi init`.

- **Workspace opt-in**: identical to `kibi-codex` — a workspace is opted in
  only when its Kibi project root owns `.kb/manifest.json`. Non-Kibi
  workspaces get no hooks output, no tracking, and an empty MCP tool catalog.
- **SessionStart** (opted in): injects a short context pointing at
  `kb_search`/`kb_query` discovery, the `kibi-usage` skill, and `kb_status`
  freshness checks.
- **PreToolUse** (`Edit|MultiEdit|Write|apply_patch`): direct `.kb/` edits get
  an advisory `additionalContext` warning to use Kibi MCP tools instead.
- **PostToolUse**: records `kb_*` MCP tool usage (including impact checks)
  and canonical workspace-relative paths from file-mutating tools only
  (`Edit`, `MultiEdit`, `Write`, `apply_patch`); read-only tool calls with
  path arguments never count as changes. State is namespaced per host session
  (`session_id`, hashed on disk), and a later edit to a path invalidates an
  earlier impact check for that exact path.
- **Stop**: emits an impact-check or freshness reminder naming canonical
  workspace-relative paths that changed during this session without a
  corresponding covering `kb_check`.

## Development

```bash
bun run build:zcode      # tsc + copy plugin assets + sync skills mirror
bun test packages/zcode  # unit tests
bun run typecheck:zcode  # tsc --noEmit
```

`scripts/sync-plugin-manifest-versions.ts` keeps
`.zcode-plugin/plugin.json`'s `version` in sync with `package.json` during
`changeset version`.

## Install (dogfood / local marketplace)

1. `bun run build:zcode` in this repository — a marketplace install from a
   local directory copies the plugin directory as-is, so a tree without a
   build is missing `dist/hook-runner.js` and every hook fails to start.
2. ZCode → **Settings → Plugin Management → Discover** → **`+`** → choose
   **local directory** and select the repository root (the directory that
   contains `.claude-plugin/marketplace.json`).
3. Install `kibi-zcode` from the **Kibi** marketplace.

Restart the ZCode session after rebuilding the plugin so hooks and MCP pick up
the new `dist/` output.

**GitHub-source installs are unsupported**: the source tree does not contain
the generated `dist/hook-runner.js`, so adding `Looted/kibi` as a GitHub
marketplace cannot produce a working plugin. `prepack` builds only run for
npm packaging flows (`npm pack`, `npm install kibi-zcode`); ZCode's
marketplace copy never builds anything.

Manual MCP fallback (no plugin install required):

```json
{
  "mcpServers": {
    "kibi": {
      "command": "npx",
      "args": ["--no-install", "kibi-mcp"]
    }
  }
}
```
