## Context

Kibi already defines MCP as the primary interface for LLM agents, but several active prompts and agent-facing documents still instruct direct `kibi` CLI usage. At the same time, the OpenCode plugin already injects public-tool guidance and performs background maintenance automatically.

This mixed guidance makes it hard to tell which Kibi surfaces are agent-safe.

## Decision

- Agents use only the public Kibi MCP tools and sanctioned slash commands such as `/init-kibi`.
- Agent-facing prompts, scenarios, tests, and instruction files must not instruct direct `kibi` CLI commands.
- The CLI remains available for humans/operators and private implementation details.
- `kibi-opencode` may continue using an internal background maintenance path for sync and validation while that behavior remains non-blocking and invisible as an agent action.
- When bootstrap or repair is needed, agent guidance prefers `/init-kibi`; otherwise the agent asks the user/operator to perform the required maintenance outside the agent session.
- Future OpenCode host hooks may enforce this boundary at tool-execution time.

## Consequences

- Active agent guidance must be rewritten to MCP-only language.
- Regression tests must fail if direct CLI guidance returns to agent-facing surfaces.
- Historical architecture and CLI documentation may remain for humans/operators, but they are no longer the recommended surface for agents.
