## Context

MCP sessions can remain attached to a git branch while external tooling rebuilds the same branch KB (for example via `kibi sync --rebuild`).
The server previously relied on branch-switch detection alone, so external same-branch KB replacement by `kibi sync --rebuild` left the MCP session serving stale in-memory Prolog data until a full restart.

The KB layer needs a cheap, deterministic, and in-band signal to detect when an attached branch snapshot is no longer the active one before any query is accepted.

## Decision

The MCP server should detect external branch KB replacement using directory/file modification metadata before processing interactive operations:

1. Capture a branch-specific KB stamp on attachment from `packages/mcp/src/server/kb-freshness.ts`:
   - `BranchKbStamp` from `readBranchKbStamp`, using both directory mtime and branch KB file mtime.
   - `sameBranchKbStamp` to compare current and attached stamps.
2. Track the attached stamp in session state (`attachedBranchStamp`) after each attach.
3. Before serving KB operations, validate the current stamp via `sameBranchKbStamp`.
4. If stale, re-read the branch KB with `refreshAttachedBranchKb`:
   - Retry once via `refreshAttachedBranchKbWithRetry` when the branch stamp changes between pre-attach and post-attach detection, and raise `KbRefreshError` when reconciliation cannot be completed after the retry.
   - Raise `KbRefreshError` when refresh attempts fail or cannot reconcile state.
   - Re-attach only after a successful refresh; otherwise fail closed.

## Consequences

### Positive

- Detects externally rebuilt/replaced branch KB snapshots before stale reads can be served.
- Preserves normal branch behavior while adding explicit recovery for same-branch race conditions.
- Keeps fast-path checks inexpensive by using filesystem metadata instead of expensive content hashing.
- Provides deterministic retry handling when the branch stamp changes during the attach window, guarding against concurrent external writes.

### Negative

- Requires MCP sessions to perform lightweight file-system checks on touched commands.
- Refresh failures are now treated as hard errors (`KbRefreshError`) when recovery cannot be guaranteed.

### Neutral

- Existing in-process refresh-on-branch-change behavior remains intact; this ADR only adds stat-based same-branch validation.
- Symbol/API behavior remains unchanged for successful refreshes; observability improves via existing error/sync channels.

## Verification

- Add/maintain MCP regression coverage for the same-branch replacement path in `packages/mcp/tests/server`.
- Ensure transient failure handling is exercised (retry path then fail-closed behavior).
- Validate docs and release metadata reflect this behavior in MCP and CLI references.
