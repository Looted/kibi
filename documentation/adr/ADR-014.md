## Context

Kibi previously relied on a mix of manual and ad-hoc scripts for versioning and publishing npm packages (core, cli, mcp, opencode). This approach led to inconsistencies, risk of human error, and lack of traceability in release operations.

## Decision

**Adopt [Changesets](https://github.com/changesets/changesets) for release management.**

- **Release on Master**: `master` is the only branch where releases are published to npm. The `master` CI workflow detects unpublished versions and publishes them.
- **Versioning on Develop**: All version bumps and changelog updates happen on `develop` (or feature branches). No version-related commits are made on `master`.
- **Selective Publishing**: CI only publishes packages whose local version is missing from the npm registry. No back-merges are required as `master` creates no new content.
- **No Direct Publish**: Manual `npm publish` is prohibited. All releases must go through the `develop` -> `master` merge flow.

## Rationale

- Changesets is a widely adopted, open-source tool for multi-package monorepos
- Provides atomic, auditable release operations with changelog generation
- Integrates with GitHub Actions and other CI/CD systems
- Reduces risk of inconsistent or accidental releases
- Enables traceability and reproducibility for all published artifacts

## Implications

- All contributors must use the documented Changesets workflow for releases
- CI/CD pipelines must enforce Changesets-based release gates
- Documentation and KB must be updated to reflect this policy

## Fallback Guidance

If KB query is unavailable or unreliable, agents and maintainers MUST refer to this ADR and REQ-020 for authoritative release policy. Documentation is the source of truth in case of KB instability.

## Status

Accepted and implemented as of 2026-03-11.
