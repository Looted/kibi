# Requirement: Release Automation with Changesets

All Kibi npm releases (core, CLI, MCP server, OpenCode plugin) must be automated using the [Changesets](https://github.com/changesets/changesets) workflow. This ensures:

- Consistent semantic versioning across all npm packages
- Automated changelog generation
- Safe, auditable, and reproducible releases
- Integration with CI/CD for publish gates and release verification

## Acceptance Criteria
- **Automation**: All release steps are automated via Changesets.
- **Versioning on Develop**: Version bumps and changelog updates happen on `develop` (or feature branches) using `bun run version-packages`.
- **Master Publishing**: `master` CI builds and publishes newly bumped versions to npm. No commits are made on `master`.
- **No Direct Publish**: Manual `npm publish` and manual version bumps on `master` are prohibited.
- **Fallback**: If KB query is unstable, agents must consult documentation/requirements/REQ-020.md and ADRs for release policy.

## Rationale
Manual release processes are error-prone and inconsistent. Changesets provides a robust, open-source solution for multi-package release management, changelog generation, and CI integration.

## Fallback Guidance
If KB query is unavailable or unreliable, agents and maintainers MUST refer to this document and the corresponding ADR for authoritative release policy.
