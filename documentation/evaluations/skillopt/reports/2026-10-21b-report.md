# Kibi SkillOpt campaign — 2026-10-21b

## Outcome

**kibi-traceability** is confirmed with no regression. Over 30 cells per arm it went from 82.33 to 93.17, and hard passes went from 22/30 to 26/30. The gain is in executable-coverage, which rose from 51.67 to 95.83.

**kibi-usage** was not confirmed. Its candidate fixed the intent-consult call order: 6/6 cells were complete, against 3/6 for the baseline. Over 30 cells per arm the mean went from 75 to 75.5, but validation-recovery regressed from 100 to 80, so confirmation failed with `confirmation_noregression_failed`.

Canonical skills are unchanged. The packaged traceability file is a review proposal, and adopting it needs explicit approval of its hash.

## Scope and method

This is the first campaign on the fixed harness:

- `ts-morph` is staged in the evaluation MCP runtime, and a symbol-capability readiness probe runs before paid work.
- The executable-coverage objective expects verification `dirty`. It is seeded without the target coverage link, so the agent must write that edge itself.
- The usage rubric requires `kb_model` mode `requirement` only for strict-property and rule lanes.
- Declared project-local predicate schemas are seeded.
- Kibi's applicability gate accepts an explicit `schemaId` whose names the claim contains.

The fixture-setup routes need built packages. The first smoke attempt failed before any cell with a missing CLI build output and cost 0 cells. After `bun run build` the tracked tree was still clean, and it stayed clean for the whole run.

Host: Claude Code CLI 2.1.306 (`KIBI_SKILLOPT_HOST=claude-code`). Optimizer **claude-opus-5-5 / high**; target **claude-haiku-5-5 / low**. The target cap was 300 episodes, of which 290 were used. Source tree: develop plus the harness fixes at `dfa442a63`, unchanged for the whole run.

The traceability baseline is the skill adopted from the 2026-10-21 campaign (`7837d4e7…`). The usage baseline is unchanged (`b1e2610d…`).

Rounds:

1. **Smoke**: 1 repeat, baseline plus one composed candidate per skill, 10 cells per skill. It checked that the fixes work live.
2. **Round 1**: two optimizer candidates per skill, 2 repeats, 10 cells per arm. Each candidate came from public feedback naming the weak family and its first missing required call or wrong final state.
3. **Round 2**: the best round-1 candidate alone, plus a composition of both round-1 insertions.
4. **Round 3** (usage only): a second-round optimizer candidate aimed at intent-consult, plus its composition with the round-1 winner.
5. **Final evaluation**: the selected candidate alone against the baseline on a fresh fixture root, 3 repeats, 15 cells per arm.
6. **Confirmation**: 3 more repeats on a fresh cohort, combined with the final cohort to 30 cells per arm.

Scores, hard passes, worst family and the ordering columns follow the definitions in the [2026-10-04 report](2026-10-04-report.md). A cell scores 60 for the final state with no critical failure, 25 for the required call order and 15 for isolation. This is a small repeated development comparison. There was no held-out run, and no significance is claimed.

## Remaining gaps

- **usage safe-mutation-direction** has never hard-passed: 0 of 32 cells in this campaign and 0 of 54 in the previous one, with a maximum of 40. Every cell records `final-safe-mutation-direction` and `workflow-outcome`.
  - The relationship endpoints the request names are not in the seeded knowledge base. They exist only as documents outside the configured Kibi paths.
  - The only import route offered is a CLI migration, which the MCP-only task excludes.
  - As a result, agents either stop after the dry run (first missing call `kb_upsert`, 2/6 per arm) or have the real write refused because the target does not exist.
  - This looks like a fixture defect and needs harness review before skill text is aimed at it. No candidate in this campaign changed the family.
- **usage validation-recovery**: the candidate lost 2 of 6 cells on the final state while completing the full call order. The 2026-10-21 campaign showed the same pattern: the agent changed more than the invalid field.
- **traceability scenario-feasibility** stays at 60–70 in both arms. The call order is complete, and the critical failure is always `workflow-signal-4`, one answer signal.
- **usage fact-predicate-modeling**: about one cell in six per arm stops after `kb_model` without writing (first missing call `kb_upsert`).
- **usage intent-consult**: with the candidate the call order was complete in 6/6 cells, but 2/6 cells per arm still lose `workflow-signal-2`.
- **Product gap**: `kb_upsert` with `dryRun: true` accepts payloads that the real write then refuses, for mixed `executable_for` ownership and for a missing relationship target.
