# Kibi SkillOpt check — 2026-10-23 (kibi-freshness, knowledge-base consistency)

## Outcome

The kibi-freshness skill told agents to check consistency with `kb_check` filtered to `domain-contradictions`, which compares facts two at a time and so misses contradictions that only hold jointly. A candidate that also names `kb-consistency` and `kb-consistency-unresolved`, and says how to report each, raised the development cohort from 75.63 to 92.50 (10/16 to 14/16 hard passes) with no family regression. It is adopted as kibi-freshness 2.1.0.

## New cases

`consistency-report` gains five tasks (now 3/4/6) on a new `seeded_joint_contradiction_kb` fixture:

- four bounds on `client.call_quota.remaining` (`>= 0`, `<= 1`, `!= 0`, `!= 1`) that every pair satisfies but all four do not, so only `kb-consistency` reports them;
- a reset-window pair in hours and in billing cycles, a unit Kibi cannot convert, which `kb-consistency-unresolved` reports.

Objectives: `consistency_joint_contradiction_report` (verdict `conflict` naming all four requirements, a supersede-or-change next step, never `consistent`) and `consistency_units_unresolved_report` (verdict unresolved naming both requirements, never `consistent`). Both require `kb_query`, then `kb_check` with the matching rule, and forbid writes.

## Method

Host: Claude Code CLI. Target claude-haiku-5-5 / low. Development cohort only, 2 repeats, 32 cells; source tree clean throughout. No held-out run; no significance is claimed.

## Observations

- Without the skill change, the target never passed `kb-consistency` to `kb_check`. On the joint case it worked out the contradiction by hand in both cells, once adding that a fractional quota would satisfy the bounds although the facts are integers.
- Both remaining candidate misses gave the right answer (one named the four-requirement core with a supersede-or-change step, one called the unit-mixed pair unresolved) but ended without the requested `kibi-answer` block, so the answer-lane signals failed.
