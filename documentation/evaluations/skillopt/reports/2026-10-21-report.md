# Kibi SkillOpt campaign — 2026-10-21

## Outcome

Confirmed improvements without regression: **kibi-freshness** (68.67 → 96.67, hard passes 1/15 → 13/15) and **kibi-traceability** (45.67 → 76.67, hard passes 0/15 → 10/15). **kibi-usage** was not confirmed. Its candidate raised intent-consult from 65 to 81.67, but it regressed fact-predicate-modeling and validation-recovery over a 30-cell-per-arm confirmation. Canonical skills remain unchanged; the packaged files are review proposals and need explicit approval of their hashes before adoption.

## Scope and method

This is the first campaign on the corrected harness: fixtures produce the states their expectations name, the branch check reads Git, the validation-recovery input names its target, and predicate arguments compare through Kibi's binding tokens. The previous run (2026-10-20) used fixtures that made seven families unreachable, so its numbers are not comparable with this one.

Host: Claude Code CLI 2.1.304 (`KIBI_SKILLOPT_HOST=claude-code`). Optimizer **claude-opus-5-5 / high**, target **claude-haiku-5-5 / low**. Target cap 400 episodes; 330 used. Source tree: develop at `b55baf729`, unchanged for the whole run.

Rounds:

1. **Round 1** evaluated the 2026-10-20 packaged candidates (composed unchanged as seeds) against the live baseline: 2 repeats, 10 cells per arm.
2. **Round 2** evaluated the seed and a new optimizer candidate. The new candidate came from feedback naming the first missing required MCP call per family, which was derived from broker traces and the public required-call order of each development case.
3. **Round 3** (usage and traceability only) evaluated the round-2 candidate and a new one.
4. **Final evaluation:** each selected candidate was evaluated alone against the baseline on a fresh fixture root, with 3 repeats and 15 cells per arm. For usage, this was followed by a confirmation with 3 more repeats, combined to 30 cells per arm.

Scores, hard passes, worst family and the ordering columns follow the definitions in the [2026-10-04 report](2026-10-04-report.md). A cell scores 60 for the final state with no critical failure, 25 for the required call order and 15 for isolation. This is a small repeated development comparison with no held-out run and no significance claim.

What the feedback found:

- On the corrected harness, the baseline usually reached the right final state. It lost the 25 order points because it skipped one required call:
  - freshness agents went from `kb_status` straight to `kb_check` without `kb_query`;
  - traceability agents skipped `kb_search` when an id was named, and skipped the closing `kb_status`.
- Freshness round 2 and traceability round 3 fixed exactly those gaps.
- Usage candidates that restated the modeling or mutation workflow made agents upsert before `kb_model` mode `requirement`, change an entity's type to get a dry run through, or stop before the real `kb_upsert`.
- The usage baseline itself varied between 57 and 74.5 across cohorts.
