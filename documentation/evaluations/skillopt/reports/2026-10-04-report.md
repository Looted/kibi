## Scope and method

PR #329 was merged before this run. The checkout started clean at develop commit `5e91abca8f3211eaccd149c474cd9f9d46cbce73`; all corrected comparisons use clean committed harness head `8628343364b56c10b5ec95d34096785bc2307221` on `codex/skillopt-eval-2026-10-04`. Canonical skill files were never adopted or edited. The only Kibi metadata changes are the operator-authorized generated coordinates and registrations/links for thirteen existing helper symbols.

The exact accepted profiles are **gpt-6.1-sol / xhigh** for optimization and **gpt-6-luna / low** for target episodes. Every paid command inherits the same five configuration exports. Both profiles passed the real capability canary using native Codex CLI 0.160.0 with its adjacent code-mode host; login reported ChatGPT authentication. Setup included Bun install/build, frozen uv synchronization, and offline SkillOpt tests before paid dispatch.

Published API list prices were pinned as price-equivalent inputs, in USD per million tokens: optimizer input/cached input/output **2 / 0.1 / 10** ([official Sol model page](https://developers.openai.com/api/docs/models/gpt-6.1-sol)); target **0.1 / 0.01 / 0.5** ([official Luna model page](https://developers.openai.com/api/docs/models/gpt-6-luna)). These inputs do not establish charges against the ChatGPT coding plan. Zero placeholder price amounts in episode receipts are not evidence of zero cost.

Each core development round evaluates one frozen candidate against the live baseline over five development families with two repetitions: ten cells per arm, twenty in total. The explicit target cap is thirty. Confirmation uses a fresh fixture root and three further repetitions: thirty new cells; its combined aggregate contains the selected twenty development cells plus thirty confirmation cells, twenty-five per arm. All cells are retained. Candidate generation is limited to two successful rounds per skill in this run, stopping on a positive mean change without hard-pass, family, or security regression, or after two rounds without a qualifying improvement. Selection prefers a qualifying complete comparison and otherwise the greatest baseline-relative mean change among complete comparisons. A failed confirmation is not a result.

Bootstrap ran only after all core confirmations completed and at least 61 target attempts remained. It uses four development tasks: sixteen cells per two-repeat matrix and twenty-four new three-repeat confirmation cells. A combined bootstrap confirmation contains forty cells, twenty per arm. The same cap of thirty and stopping/selection criteria apply.

Scores are the campaign's existing 0–100 development scores; hard passes are the existing rubric decisions. Worst family means the minimum family mean, including ties. This is a small repeated development comparison with no held-out run, statistical significance claim, production adoption, or general semantic-proof claim.

Ordering and answer rates below are derived from persisted host transcripts. **KB-before-edit** means at least one non-skill-catalog Kibi call before the first recorded edit, or during the episode if it has no recorded edit. It includes status and validation calls, so it does not alone establish consultation of governing intent. **Search-before-edit** applies the same ordering convention to `kb_search`. Skill list/load/read calls are excluded. **Answer** counts parsed `kibi-answer` blocks; emission alone does not establish a correct verdict, and not every core case requests this format. Tables also report recorded edit cells and how many had a preceding KB/search call. Absence of a recognized edit event is not a syscall-level guarantee that no source was edited. Honest abstentions remain visible rather than being treated as ordering failures solely for making no recorded edit.

Security counts are cells with recorded security violations or isolation sentinels. Infrastructure counts are cells whose receipt status is `infrastructure-failure`; evidence conflicts and interruptions are listed separately. Scores and failures are preserved rather than filtered out.
