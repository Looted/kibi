# Kibi SkillOpt check — 2026-10-29 (kibi-usage, quantified claims)

## Outcome

kibi-usage told agents how to ground a claim but not what to ground a quantified claim on, and it never asked for a rejection scenario. Agents modeled "every loaded file is instrumented" as a boolean verdict and specified it with one happy-path scenario. A candidate that teaches agents to ground the varying dimension (a count, set or rule) and to specify the requirement with success and rejection scenarios that each assume their input confirmed with no family regression. It is adopted as kibi-usage 2.35.0.

| quantified_dimension case, all four cells | 15, 15, 15, 40 | 100, 100, 100, 100 |

The one candidate miss in the confirmation is a compound_obligations cell that scored 75 in both arms of both runs.

## New cases

`rule-lane-modeling` grows to 0/3/2 with two claims that ask for the requirement "together with the scenarios that specify it":

- `quantified_dimension` (development): "Every file loaded into a module must be instrumented."
- `quantified_cardinality` (held-out): "Each organization member must hold exactly one role."

Both expect the lane `typed_dimension` (a rule fact or a non-boolean property value). They fail a boolean property value that grounds a manifest claim (`verdict-grounding`), require a specified scenario expecting rejection or error (`scenario-rejection`), and require at least two specified scenarios that set `expects` and assume a property value (`scenario-assumes`).

## Method

Host: Claude Code CLI. Target claude-haiku-5-5 / low. kibi-usage development cohort (8 tasks), 2 repeats per run, source at the harness commit with the 2.34.0 skill as baseline. No held-out run; no significance is claimed.

## Observations

- Baseline cells either stopped at the advisor's ontology-gap observation or grounded `instrumented = true` on a loaded-file subject, and wrote one scenario without `expects: rejection`.
- A first candidate (same rules, without the sentence that an assumed forbidden value is not a contradiction) produced a prose-only rejection scenario: the agent wrote that it left out the assumption "because a forbidden value would contradict the zero-count grounding fact". In one cell it also stopped at the ontology-gap observation. Stating both points explicitly (try `kb_model` mode `requirement` with an int count before the gap; assumed-value facts are linked only by `assumes`) gave 100 in every cell of the quantified case.
